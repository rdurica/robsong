# Agent workflow

Generated by `/setup`. Skills read this file after `docs/agents/config/issue-tracker.md`.

Preset: full-agentic

## Git

- branch-owner: agent   <!-- agent | human -->
- push: finalize                   <!-- finalize | never -->

**branch-owner: agent** — prepare the Delivery branch from the remote default or reuse it, following `/implement`. Preserve unfinished local work; branch switching and pull/rebase require a clean worktree.

**branch-owner: human** — agent stays on current branch; never checkout or create. User creates branch before `/implement`.

**push: finalize** — the parent orchestrator may push during `/verify` finalization and watch CI for the exact pushed SHA, for either branch owner. Only branch-owner agent opens or updates a ready PR if green or a draft PR if a gate fails. Human-owned PRs remain under user control.

**push: never** — retain verified local commits, regardless of branch ownership; skip push, CI watches and PR creation/state changes. Analysis tracker updates still follow the workflow unless the session restricts them too.

Priority: explicit session instructions (including “do not push”) > session override (`/implement #N human` changes branch-owner only) > this file. Working subagents do not commit or push; the parent handles git operations. The analysis `## Delivery` only names the branch; it does not carry branch-owner or push.



## Tracker

- active: github       <!-- github | local -->
- local-path: `docs/agents/config/`
- language: cs           <!-- en | cs -->

`local-path` identifies the tracker configuration directory. Local ticket files live in `docs/agents/analysis/`, with completed tickets in `docs/agents/analysis/done/`; do not derive their location by appending `analysis/` to `local-path`.

`/analyze` writes the analysis prose in this language — title and every section body. Section headings stay English, as do identifiers, paths and HTTP contracts. `/implement` and `/verify` comments on the **analysis** (never on the PR) use the same language. `/verify` green: `ready-to-review`, with a ready PR for agent-owned delivery when publishing is enabled. `/verify` fail: `needs-attention` (replaces `in-progress`) and a fail note; agent-owned delivery may publish a draft PR when publishing is enabled. Human-owned never manages PRs. Preserve unrelated tracker labels. These statuses are GitHub labels; the local tracker has none — a verified file moves to `done/`, a blocked one stays active with a comment.

When `active: local`, see `docs/agents/config/issue-tracker.local.md` (if present) for file conventions.

## UX review

- ux-review: disabled   <!-- enabled | disabled -->

**enabled** — `/verify` Phase 3, after code review is green; hard gate on Critical/Major; after UX fixes re-run local tooling before Ship.

**disabled** — Ship right after code review is green.

Code review itself (Phase 2) has no switch — it always runs.

## Implementation orchestration

1. The user starts `/align` → `/analyze` locally; conversation history produces the saved analysis.
2. `/implement` (Opus) orchestrates fresh `test-writer` agents, reviews RED evidence and commits tests, then delegates production code to fresh `implementer` agents (Sonnet). Checks run through `check-runner` (Haiku). Independent work runs in parallel.
3. Parent integrates, commits and automatically runs `/verify`. See `/implement` for context, test stability and isolation rules. If hooks block the intentional RED test commit, resolve the blocker without `--no-verify`.

## Work types

| Type | Pipeline | branch-owner typical |
|------|----------|----------------------|
| **feature** | `/align` → `/analyze` → `/implement` → `/verify` (functional → code review [→ ux] → ship) | agent (full-agentic) or human (human-owned) |
| **complex bug** | same as feature; `/align` if root cause unclear | agent or human |
| **simple bug** | skip `/align`; ticket with Acceptance → `/implement` | human |
| **trivial fix** | outside pipeline — direct fix + commit | n/a |

### Bug fast-path

1. Create bug issue (GitHub with `analysis` omitted, or `docs/agents/analysis/NNN-slug.md` with `Kind: bug`; next ID shared with `docs/agents/analysis/done/`) with Acceptance.
2. `/implement #issue` implements Acceptance from the ticket body, then runs `/verify`. User-invoked `/implement` does not need `ready-for-agent`.

## Session override

User may pass `/implement #N human` or `/implement #N agent` to override branch-owner for one session.

This changes branch ownership only. To disable pushing for the session, state that explicitly.
